PART 1: LANGUAGE & TECHNOLOGY CHOICES
================================================================================

PRIMARY LANGUAGE: C++ (Arduino/PlatformIO)
    • Already familiar - you're using it for ESP32
    • Direct memory control
    • Fast execution (needed for real-time ML)
    • Large ecosystem for TensorFlow Lite

TECHNOLOGY STACK FOR ESP32:
    1. TensorFlow Lite Micro (for C++)
       - Designed for embedded devices
       - Supports .tflite models
       - Low memory footprint (~80KB overhead)
    
    2. Arduino IDE or PlatformIO (recommended)
       - PlatformIO better for dependency management
       - Can specify exact TFLite library versions
    
    3. Libraries needed:
       - tensorflow/lite (the core TFLite library)
       - BluetoothSerial (you already have this)
       - Wire.h (I2C for sensors - you already have)

WHY NOT Python/MicroPython?
    ✗ Slower inference on ESP32
    ✗ Limited TFLite support
    ✗ Memory constraints for complex models
    ✗ More difficult to integrate with existing C++ code

ESP32 EXECUTION FLOW:
===============================================================
┌─────────────────────────────────────────────────────────┐
│ 1. INITIALIZATION (setup)                               │
├─────────────────────────────────────────────────────────┤
│  • Initialize sensors (MPU6050, MAX30102, NTC, ADC)     │
│  • Load TFLite model from PROGMEM (flash memory)        │
│  • Initialize interpreter + allocate tensors            │
│  • Initialize BluetoothSerial                           │
└─────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────┐
│ 2. DATA COLLECTION LOOP (every 2 seconds)               │
├─────────────────────────────────────────────────────────┤
│  • Read raw sensor values:                              │
│    - Temperature: Thermistor (GPIO36)                   │
│    - Pressure (4 zones): ADC pins GPIO 32,33,34,35      │
│    - SpO2/HR: MAX30102 via I2C                          │
│    - Accel/Gyro: MPU6050 via I2C                        │
│    - Steps: Detect from accelerometer peaks             │
└─────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────┐
│ 3. FEATURE ENGINEERING                                  │
├─────────────────────────────────────────────────────────┤
│  Create 15-feature vector:                              │
│                                                         │
│  Raw Features (11):                                     │
│    [0-3]:   Temperatures (heel, ball, arch, toe)        │
│    [4-7]:   Pressures (heel, ball, arch, toe)           │
│    [8]:     SpO2                                        │
│    [9]:     Heart Rate                                  │
│    [10]:    Step Count                                  │
│                                                         │
│  Engineered Features (4):                               │
│    [11]:    max_pressure = max(pressure array)          │
│    [12]:    pressure_variance = var(pressure array)     │
│    [13]:    max_temp = max(temp array)                  │
│    [14]:    temp_variance = var(temp array)             │
│                                                         │
│  Then NORMALIZE using saved scaler values               │
│  (multiply by scale, subtract offset)                   │
└─────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────┐
│ 4. ML INFERENCE (TFLite)                                │
├─────────────────────────────────────────────────────────┤
│  • Load 15 features into input tensor [1×15]            │
│  • Run interpreter.invoke()                             │
│  • Extract output: probability (0-1)                    │
│  • Convert to risk level:                               │
│    - < 0.3: LOW_RISK                                    │
│    - 0.3-0.6: MODERATE_RISK                             │
│    - > 0.6: HIGH_RISK                                   │
└─────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────┐
│ 5. PREPARE BLUETOOTH PACKET (COMPREHENSIVE)              │
├─────────────────────────────────────────────────────────┤
│  Send everything the App needs to display + store:      │
│                                                          │
│  SENSOR DATA (Raw Values):                              │
│  Byte 0:     Temp Heel (int8: offset by 25, multiply 2) │
│  Byte 1:     Temp Ball (int8: offset by 25, multiply 2) │
│  Byte 2:     Temp Arch (int8: offset by 25, multiply 2) │
│  Byte 3:     Temp Toe (int8: offset by 25, multiply 2)  │
│  Byte 4:     Pressure Heel (uint8: pressure/0.3)        │
│  Byte 5:     Pressure Ball (uint8: pressure/0.3)        │
│  Byte 6:     Pressure Arch (uint8: pressure/0.3)        │
│  Byte 7:     Pressure Toe (uint8: pressure/0.3)         │
│  Byte 8:     SpO2 (uint8: direct %)                     │
│  Byte 9:     Heart Rate (uint8: direct bpm)             │
│  Byte 10-11: Step Count (uint16 big-endian)             │
│                                                          │
│  ML PREDICTIONS (Calculated):                           │
│  Byte 12:    Risk Probability (uint8: 0-100)            │
│  Byte 13:    Risk Level (uint8: 0=LOW, 1=MOD, 2=HIGH)   │
│  Byte 14:    Battery Level (uint8: 0-100%)              │
│  Byte 15-16: Timestamp (uint16: relative seconds)       │
│                                                          │
│  TOTAL: 17 bytes per packet                             │
│  Frequency: Every 2 seconds (as before)                │
│                                                          │
│  *** IMPORTANT: Keep byte-for-byte format consistent *** │
│  *** App will parse same positions every time         *** │

┌─────────────────────────────────────────────────────────┐

PART 5: KEY TECHNICAL CHALLENGES & SOLUTIONS
================================================================================

CHALLENGE 1: TFLite Model File Size
────────────────────────────────────
    Problem: .tflite file (~50-100KB) too large for binary inclusion
    Solution: Use xxd to convert to hex, create .h header file
    Tool: `xxd -i random_forest_model.tflite > model_data.h`

CHALLENGE 2: Quantization / Model Size
───────────────────────────────────────
    If model still too large:
        • Quantize to int8 (reduces 2-3x with minimal accuracy loss)
        • Already done in your Python notebooks
        • Use quantized .tflite if available

CHALLENGE 3: Normalization Accuracy
─────────────────────────────────────
    Must match Python StandardScaler exactly:
        normalized = (raw - mean) / std
    
    Store as constants in config.h with HIGH PRECISION (float32)
    Extract from: ML/02_random_forest_model.ipynb (scaler.mean_, scaler.scale_)

CHALLENGE 4: Inference Latency
───────────────────────────────
    Expected on ESP32: 20-50ms
    Optimize if > 100ms:
        • Use compiler optimization -O2
        • Reduce feature count if possible
        • Profile with micros() timer

CHALLENGE 5: Limited RAM
─────────────────────────
    TFLite mallocs ~50KB for inference buffers
    Total available ESP32 RAM: ~160KB free (after WiFi/BT stack)
    Solution:
        • Use static allocation where possible
        • Reuse buffers (don't allocate in loop)
        • Disable Serial debugging in production
